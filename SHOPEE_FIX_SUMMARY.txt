================================================================================
SHOPEE SYNC BATCH PROCESSING FIX - SUMMARY
================================================================================

PROBLEM ANALYZED:
- Shopee platform shows 38 READY_TO_SHIP待发货订单
- sync_logs repeatedly shows: "synced 0/20 orders" with status=failed
- ERP订单数量与 Shopee 不一致
- No clear error messages explaining why batches fail

ROOT CAUSES IDENTIFIED:
1. HTTP 500 / Gateway errors in get_order_detail API calls were not retried
2. Invalid/missing order_sn values were not validated before API calls
3. Failed batch = all 20 orders marked as failed (no partial success tracking)
4. Error messages didn't include requested order_sns for diagnostics

FIXES IMPLEMENTED:
================================================================================

FIX #1: Add Retry Logic for get_order_detail
────────────────────────────────────────────
File: supabase/functions/shopee-sync-orders/index.ts (line 209-237)

What changed:
  - Try get_order_detail API up to 3 times
  - Use exponential backoff: 1s, 2s, 4s between retries
  - Only fail after all 3 retries exhausted
  - Log the actual error reason instead of generic failure

Before:
  const detailResp = await shopeeGet(...);  // Throws on any HTTP error

After:
  for (let retry = 0; retry < 3; retry++) {
    try {
      detailResp = await shopeeGet(...);
      break; // Success
    } catch (e) {
      if (retry < 2) {
        await new Promise(...); // Wait and retry
      } else {
        // Log detailed error after all retries failed
        return { syncedOrders, syncedItems };
      }
    }
  }

Expected improvement:
  ✅ Temporary API failures (500, gateway timeout) now recoverable
  ✅ "synced 0/20" from transient errors → automatically retried
  ✅ Real errors logged with specific Shopee error codes


FIX #2: Validate order_sn Before Batch Processing
──────────────────────────────────────────────────
File: supabase/functions/shopee-sync-orders/index.ts (line 502-515)

What changed:
  - Filter order_sns to remove empty/invalid values
  - Log when API returns fewer orders than requested
  - Skip batch processing if all order_sns are invalid

Before:
  const orderSns = pageOrders.map((o) => o.order_sn);
  const pageResult = await upsertShopeeOrderBatch(..., orderSns);

After:
  const orderSns = pageOrders
    .map((o) => String(o.order_sn || "").trim())
    .filter((sn) => sn.length > 0);

  if (orderSns.length > 0) {
    const pageResult = await upsertShopeeOrderBatch(..., orderSns);
  } else {
    // Skip if all order_sns invalid
  }

Expected improvement:
  ✅ Invalid order_sns filtered before API call
  ✅ Avoid passing empty strings to Shopee API
  ✅ Distinguishes between "API has no data" vs "API data is malformed"


FIX #3: Better Error Diagnostics for Batch Failures
────────────────────────────────────────────────────
File: supabase/functions/shopee-sync-orders/index.ts (line 242-258)

What changed:
  - Log requested order_sns when batch fails
  - Include sample data when orders returned 0 results
  - Track when API returns partial results (10/20 vs 0/20)

Before:
  message: `batch of 20 order_sns returned 0 results...`

After:
  message: `batch of 20 order_sns returned 0 results.
           requested: 123456,789012,345678...`

  OR if partial success:
  message: `batch of 20 order_sns returned 10 results
           (some may be deleted/hidden). got: 123456,789012...`

Expected improvement:
  ✅ Can see exact order_sns that failed
  ✅ Distinguish "API has 0 data" from "API returned some"
  ✅ Debug mismatch between list API and detail API
